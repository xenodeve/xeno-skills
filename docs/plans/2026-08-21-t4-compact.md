# T4-Compact — a compaction that cannot happen without a handoff

**Status:** design, not started. **PRD: #304**; slices #305 (probe) · #306 (validity) · #307 (gate) · #308 (skill) · #309 (restore), attached as native sub-issues.
**Source of the concept:** `C:\AI\docs\researchs\Qwen3.8-27B_Optimization_Research_Docs\07-CONTEXT-KV-CACHE-T4-COMPACT.md` §9 (2026-08-17), restated by the developer on 2026-08-21 as a *software layer the model calls*.

---

## 1. The step that cannot be built, and why the design survives it

The concept asks for a layer that, on a signal from the model, runs `/handoff`, then `/compact`, then
feeds the model a prompt telling it to read the handoff by path.

**The middle step is not available to any code we can write.** Compaction is owned by the harness:

- **`/compact` is a user command.** The model has no tool for it, and a hook cannot type into the session.
- **The harness compacts on its own.** Verified as strings in the shipped binary
  (`@anthropic-ai/claude-code/bin/claude.exe`): `tengu_auto_compact_succeeded`,
  `tengu_auto_compact_circuit_breaker`, `tengu_auto_compact_rapid_refill_breaker` — an auto-compaction
  path with its own breakers, on a threshold we do not set.

**So the layer inverts.** Instead of *the model deciding when compaction happens*, the layer makes
**every** compaction — auto or manual — arrive at a session that already has a valid handoff. The
trigger stays the harness's; the **guarantee** becomes ours, and the guarantee is the part that was
load-bearing all along:

```text
NO VALID HANDOFF → NO COMPACT
```

That invariant is mechanically enforceable **today**, which the original design did not know.

## 2. What the binary actually supports (verified 2026-08-21)

Extracted from `bin/claude.exe` with `grep -a`:

| Fact | Evidence string |
|---|---|
| A `PreCompact` hook event exists | `"PreCompact"` in the hook-event list, next to `PostCompact`, `SessionStart`, `Stop`, … |
| **It can block compaction** | `Compaction blocked by PreCompact hook` · `compaction blocked by PreCompact hook; continuing uncompacted` |
| It distinguishes manual from automatic | the `auto` matcher string sits in the same table; the documented pair is `manual`/`auto` |
| It receives compaction instructions | `custom_instructions` |
| A `PostCompact` hook event exists | `executePostCompactHooks` |
| Hooks can add context | `additionalContext` |

**Blocking exists; the exact contract does not follow from a string.** Whether a block is `exit 2`, a
`{"decision":"block"}` JSON body, or a `hookSpecificOutput` field is **unknown** and is slice 1.

**Already true in this repo:** `SessionStart` is wired with matcher `startup|clear|compact`
(`hooks/hooks.json`), so a post-compaction injection point exists and is proven — #182 measured four
injections in one session. The restore step needs no new event.

## 3. The layer, step by step, against real mechanisms

| Step in the concept | Mechanism | State |

## 4. When the skill fires — the developer's four conditions, made checkable

The concept names four. Each needs a **checkable form**, or it is a mood:

1. **Context is long.** Checkable only against a number the harness exposes; if none is reachable, the
   proxy is *turns since the last boundary* plus the transcript's byte size, and the threshold is
   **measured before it is written down**, not guessed.
2. **A task finished and the next has not started.** This is the strongest signal and the cheapest: the
   ledger/issue state changed to closed and no new issue is in flight. It is also the one the agent
   already knows without measuring anything.
3. **Long context raises the error rate.** *Unknown here* — this repo has no such measurement. The
   adjacent project has the depth data (`C:\AI` E11–E13, report 03), and the honest position is that
   condition 3 is a **hypothesis** until one of the two repos measures it.
4. **The free context does not fit the next task.** Requires an estimate of the next task's size; the
   defensible version is *the plan's change inventory is larger than what is left*, which the survey
   rule already produces.

**Conditions 1 and 2 are shippable; 3 and 4 are stated as hypotheses with their measurement named.**
Shipping 3 as if it were measured is exactly the failure `no verdict before evidence` describes.

## 5. The decision this design must not fudge: blocking `auto`

Blocking a **manual** `/compact` is safe — the developer is present, sees the reason, and can act.

**Blocking an automatic compaction is not.** Auto-compaction fires because the window is nearly full;
a hook that refuses it leaves the session with no room and no way out — and the harness's own message
is `continuing uncompacted`, which is the worst of both.

**So the policy is asymmetric, and it is the core decision of this plan:**

| trigger | handoff valid | behaviour |
|---|---|---|
| `manual` | yes | allow |
| `manual` | no | **block**, with the reason naming the path it looked at |
| `auto` | yes | allow |
| `auto` | no | **allow**, emit a warning, and **record the event** so the rate is measurable |

The recorded rate is what tells us later whether the skill's conditions fire early enough. A layer that
blocks and a layer that records are not the same product; this one does both, on different triggers.

## 6. Slices

1. **Probe the `PreCompact` contract** on this build — how a block is expressed, what the input carries
   (`trigger`, `custom_instructions`, transcript path). Output: a fixture + findings comment. **No
   shipped behaviour**, because the rest is guesswork without it.
2. **Handoff path convention + validator.** What makes a handoff *valid*: session-keyed path, non-empty,
   carries the required sections, and is **newer than the last compaction boundary**. A stale handoff is
   worse than none — it restores a session that no longer exists.
3. **The `PreCompact` hook**, implementing §5's table.
4. **The skill `t4-compact`** — conditions 1 and 2 as triggers, 3 and 4 as stated hypotheses; what it
   writes; and the one line it says to the developer (*"handoff written at `<path>` — `/compact` when
   you're ready"*), since it cannot compact by itself.
5. **Restore assertion** — a test that the post-compaction injection names the handoff **by path**, so
   the model reads the file rather than trusting the summary.

Slices 2–5 each carry a `tests/` suite; slice 1 carries a fixture and a finding.

## 7. What this plan deliberately does not do

- **It does not re-plan #182 or #184.** Injection cost and boundary-aware presence counting are done.
- **It does not build the nine-state machine** from the source document. Eight of those states describe
  a flow whose middle step we cannot own; the invariant is the part that pays.
- **It does not touch the delegation layer.** `BrainstormRequest v1` governs a different prompt.
