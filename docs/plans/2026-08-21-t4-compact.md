# T4-Compact — the layer outside the session that the agent calls

**Status:** design, not started. **PRD: #304**; slices #305 (probe the transport) · #314 (the supervisor) · #306 (handoff validity) · #307 (the gate) · #308 (the skill) · #309 (restore) · #312 (`t4-agent-memory` row). Tracking issue #310.
**Source of the concept:** `C:\AI\docs\researchs\Qwen3.8-27B_Optimization_Research_Docs\07-CONTEXT-KV-CACHE-T4-COMPACT.md` §9 (2026-08-17), specified by the developer on 2026-08-21:

> *"สร้าง software layer ครอบให้ model เรียก แล้วจะไป trigger /compact หลังจาก handoff … ตัว Model สั่ง
> Compact เองไม่ได้ … แล้วส่ง Prompt ให้อ่าน handoff ที่ตัวเองเขียนโดยส่ง Path ให้อ่าน"*

> **Revision 3, 2026-08-21.** Revisions 1 and 2 both looked for a way to make compaction happen *from
> inside the session* — first by riding auto-compaction, then by lowering its window. **Both were
> answering a question the developer had already closed.** The premise of the design is that the model
> cannot compact itself, **which is why there is a layer**. The layer is a process outside the session
> that owns it. This revision plans that process.

---

## 1. The architecture, in one picture

```text
┌─ the layer (a supervisor process) ───────────────────────────────┐
│  spawns:  claude -p --input-format stream-json                   │
│                  --output-format stream-json --session-id <uuid> │
│                                                                  │
│  ① reads the agent's stream, watching for the call               │
│  ② on a call: waits for a VALID handoff at the agreed path       │
│  ③ sends /compact into the session's input stream                │
│  ④ sends the next user message: "read <path>, then continue"     │
└──────────────────────────────────────────────────────────────────┘
        ▲                                        │
        │ ① the agent calls out                  │ ④ the agent reads its own
        │    (Bash, one command)                 │    handoff and continues
   ┌────┴────────────────────────────────────────▼──────┐
   │  the session: skill t4-compact decides the moment  │
   └────────────────────────────────────────────────────┘
```

**Everything the agent cannot do, the layer does, because the layer is not inside the conversation.**

## 2. The transport is real, and these are the flags (verified 2026-08-21, `claude --help`)

| Flag | What it gives the layer |
|---|---|
| `-p, --print` with **`--input-format stream-json`** | *"realtime streaming input"* — the layer **writes user messages into the running session**, which is the whole mechanism |
| **`--output-format stream-json`** | it reads the session's events as they happen, so it can see the agent's call and the compaction result |
| **`--session-id <uuid>`** | the layer chooses the id, so it knows the transcript path without guessing |
| `-r, --resume [id]`, `-c, --continue`, `--fork-session` | the fallback path: end the session and reopen it seeded with the handoff |
| `--replay-user-messages` | messages it injected are echoed back, so injection is **acknowledged rather than assumed** |
| `--autocompact <auto\|tokens>` | a launch-time window, sized per task class — a secondary lever, not the mechanism |
| `--bg, --background` + `claude agents` | a session managed as a background agent, if the layer should not hold the terminal |

**And it was run, not inferred — #305 is answered** (`scripts/probe-stream-transport.py`, claude 2.1.222,
2026-08-21; the events are recorded in `tests/hooks/fixtures/t4-compact-stream-transport.jsonl`):

| Question | Answer, and the observation |
|---|---|
| **Does a slash command sent as a user message execute?** | **Yes.** `/compact` produced `system/status status:"compacting"` then `status:null, compact_result:"success"`, and the `result` event for that message carried **`num_turns: 0` with zero token usage** — the command ran, the model was never called. It did not arrive as text |
| **Are the commands advertised?** | `system/init` lists 509 `slash_commands`, including **`compact`, `autocompact`, `handoff`, `claude-handoff`** |
| **Does the stream carry what the layer needs?** | Yes, but the size is a **sum of three fields**, not `cache_read` alone: `input_tokens + cache_creation_input_tokens + cache_read_input_tokens`. Measured: **50,094 → 45,591 (−9 %)** across the compaction. `cache_read` alone fell 50,005 → 26,828, which reads as −46 % and is **wrong** — the difference moved into `cache_creation`, not out of the context |
| **Is an injection acknowledged?** | Yes. With `--replay-user-messages` each injected message is echoed back as a `user` event |
| **Does the content survive?** | Yes. Eight facts were planted, then compaction ran; *"what is the codename and the port?"* answered **"Codename: FALCON Port: 8431"** from the summary alone |
| **What does the transcript record?** | One `system` / `subtype: compact_boundary`, immediately followed by a `user` record with `isCompactSummary: true` — the anchor #306's freshness check needs, and the pair `hooks/t4-segment` already reads |

**And the −9 % is the finding, not a footnote.** Compaction replaces the **conversation**, and leaves the
fixed prefix — system prompt, tools, `CLAUDE.md`, skills — untouched: here that prefix was ~26.8 K of a
~50 K context, so the compressible part was ~23 K and the summary that replaced it was ~18.8 K. **The
saving scales with how much of the context is conversation**, which in a short probe is little and in a
long session is most of it. A design that sizes its expectations from this probe would be sizing them
from the least favourable case.

**For a small-context worker the reopen path is the mechanism, not the fallback.** A `/compact` summary
measures **~50 K** and the post-compaction floor **~100 K**, so a 128 K worker compacting lands back at
~78 % full — inside the band where compaction returned **−0 %**. Reopening with a handoff the author
controls resets to *prefix + a few K* instead. Sizes and arithmetic: `docs/research/2026-08-21-compaction-yield.md`.

**So the fallback is not needed for the main path.** It stays in the plan for `DISABLE_COMPACT` and for a
future build that changes the contract — which is why the probe script says *run this, do not trust the
fixture*, and why every row above carries its date.

**If slash commands do not execute over that transport**, the fallback is already in the flag list and is
arguably better: the layer **ends the session and reopens it** (`--resume --fork-session`, or a fresh
`--session-id`) with the first user message being *"read the handoff at `<path>`"*. That is a harder
reset than `/compact` — nothing stale survives at all — and it is entirely under the layer's control.

## 3. How the agent calls the layer

**The agent has `Bash`. That is the call.** No new tool is needed and none exists — `sdk-tools.d.ts`
lists every tool input type and there is no `SlashCommand` and no compact.

```text
skill t4-compact decides the moment
  → writes the handoff to .claude/t4-handoff/<session-id>.md
  → runs:  .claude/hooks/t4-compact-call <reason>
           (writes .claude/t4-compact/request.json and returns immediately)
  → says one line and stops
```

The layer is watching for that file — or for a sentinel in the output stream, which #305 decides between.
**The agent never blocks on the layer**, because a turn that waits for its own supervisor is a deadlock.

## 4. When the skill calls — the four conditions

| Condition | Checkable form | Ships as |
|---|---|---|
| **A task finished and the next has not started** | the issue closed, nothing new in flight — the agent knows without measuring | **trigger** |
| **Context is long** | the layer sums `input + cache_creation + cache_read` from the stream | **trigger, and the threshold is now measured**: do not call below **~150 K** and expect a real return only above **~250 K** — 113 real compactions, `docs/research/2026-08-21-compaction-yield.md` |
| **What is left does not fit the next task** | the change inventory from the survey is larger than the remaining window | **trigger, layer-side** — only the layer has the usage number |
| **Depth raises error risk** | — | **hypothesis.** The adjacent project's depth data reads **100 % (30/30) at 64K** and **100 % (10/10) at a 114,406-token prompt** (`03-DEEP-CONTEXT-QUALITY-REPORT.md`, lines 94 and 160, read directly). One quantization, and *no degradation detected* is not *equivalence shown*. Nothing triggers on it |

**And every trigger inherits one floor.** A compacted session costs **~70–105 K** whatever it was — system prompt, tools,
`CLAUDE.md`, skills, and the summary — so a boundary reached at 80 K is a boundary *at* the floor: **write the handoff,
do not ask for the compaction.** Measured: below 150 K the median return is **−0 %**, and **13 of 113 compactions came
back larger**, every one of them between 90 K and 110 K.

**Condition 3 becomes checkable only because the layer exists** — the usage number lives in the stream,
not in the session. That is the second reason for the layer, after the compaction it can perform.

## 5. The guard, and why it stays even though the layer is in charge

```text
NO VALID HANDOFF → NO COMPACT
```

The layer enforces it by construction: it does not send `/compact` until the handoff validates. **The
`PreCompact` hook stays anyway**, because a compaction can still arrive that the layer did not schedule —
the harness's own, at the ceiling.

| trigger | handoff valid | behaviour |
|---|---|---|
| `manual` | yes | allow |
| `manual` | no | **block**, naming the path it looked at |
| `auto` | yes | allow |
| `auto` | no | **allow**, warn, and **record the event** |

Blocking an automatic compaction still wedges a session that is out of room; the recorded rate is what
says whether the skill and the layer are firing early enough. *(Verified: `PreCompact` can block —
`Compaction blocked by PreCompact hook`; `compaction blocked by PreCompact hook; continuing uncompacted`.)*

## 6. Restore: the layer's own next message

The concept's last step — *"ส่ง Prompt ให้อ่าน handoff … โดยส่ง Path ให้อ่าน"* — is the layer writing one
user message after the compaction completes. **That is stronger than the hook path**, because it is a
real user turn rather than injected context, and `--replay-user-messages` acknowledges it.

`SessionStart` (matcher `compact`) and `PostCompact` remain as the **belt** for compactions the layer did
not cause; slice #309 asserts that whichever injection fires **names the handoff by path** — and, per the
addon, the thinking-record map beside it.

## 6a. What the layer is actually worth: a smaller floor and a reason not to re-derive

**The value is not the compaction ratio.** The harness already reaches 88 % at the ceiling without any
of this. Two things here are not available any other way:

**1. The floor gets smaller, and that is arithmetic, not opinion.** The measured post-compaction floor is
**~100 K, of which ~50 K is the summary** (`docs/research/2026-08-21-compaction-yield.md`). A handoff plus
a one-line-per-record map is **~3–5 K**. Replacing the summary with them takes the floor to **~55 K** —
which on Claude Code lowers the bottom of every sawtooth, and on a **128 K worker is the difference
between viable and not**: 78 % of the window occupied becomes ~43 %.

**2. The conclusion survives with a route back to the reasoning.** A summary keeps *what was decided* and
loses *why*, and the loss is invisible — nothing in the restored context says a question was ever
settled. **Measured in this repository, in the session that wrote this plan:** revision 1 rode
auto-compaction, revision 2 lowered the auto-compact window, and **both were the same mistake** — hunting
for a trigger inside the session, which the developer had ruled out before revision 1 existed. The reason
it repeated is exactly the failure the record layer removes: the *conclusion* was carried forward and the
*reasoning that closed the question* was not.

**So the mechanism is: conclusion in context, reasoning on disk, index in context.** The model reads one
line per settled question and opens a record only when its current question matches one. That is
`t4-agent-memory`'s retrieval-first rule applied at the timescale of a single session rather than across
sessions.

**And the one thing that decides whether it works is a trigger, not the artifact.** A map in context that
nobody opens costs ~1 K and prevents nothing. The moment it must fire is **before re-opening a question
that looks settled** — the same shape as the four trigger fixes this repository landed on 2026-08-19,
where the rule was never ambiguous and still did not fire because it had no moment. **The cheap proxy for
whether it works: count the decisions a session re-opens after a boundary.** That number is countable
today, needs no harness, and is the measurement #312 says does not exist.

## 6b. The worker is not always Claude Code, and that inverts the economics

**Everything in §2 is one harness's interface.** `/compact`, `--autocompact`, `PreCompact`,
`--input-format stream-json` — a `codex`, `antigravity`, `cursor` or OpenCode worker has none of them.
So the layer has **one portable mechanism and one adapter**, not one design:

| Harness | cost of carrying a long context, per turn | what a compaction costs there | so |
|---|---|---|---|
| **Claude Code** | **∝ context** — every turn re-reads it from cache | one summary + a cache rewrite | **compact often**; the measured saving is ~2.3× |
| **A local model** (llama.cpp / OpenCode) | **≈ constant while appending** — measured **~40 tokens evaluated per turn instead of ~3,900**, 2.4–3.9 s | **a full re-prefill: 0 % of the prefix cache is retained.** Measured 11–12 s at 4 K, and the slope puts 64 K at **248 s** | **almost never compact.** There is no per-turn saving to amortise it against |
| **A `clink` leaf** (`codex`/`antigravity`/`cursor`) | one-shot, zero conversation context | — | irrelevant; **size the leaf** |

**On a local worker the two costs are exactly inverted.** Carrying context is nearly free while the
prefix is frozen; *changing* the prefix is the expensive event — and **a compaction is by definition a
change above the append point**. Compacting a local session to save room is paying minutes of prefill
for a saving that harness does not charge for.

**Which is why the portable mechanism is the reopen, not the compaction.** *Write a handoff, end the
session, start a new one, tell it to read the file* needs **no harness feature at all** — it works on
every worker in the fleet, including ones that do not exist yet. `/compact` over stream-json is a
**Claude Code optimisation of that same flow**, worth having because it keeps the master's own session
alive, not because it is the general case.

**So the ordering in §3 is corrected: reopen is primary and portable; the in-session compaction is the
Claude Code adapter.** The invariant and the handoff artifact are what both paths share, and they are
the only parts that must never be harness-specific.

## 8. What this plan deliberately does not do

- **It does not put the trigger inside the session.** Revisions 1 and 2 tried; the model has no tool and
  a hook cannot type. The layer exists precisely to hold what the session cannot.
- **It does not automate the console.** The stream-json transport is a supported interface; SendKeys
  against a TUI is not, and would break the first time the terminal changed.
- **It does not re-plan #182 or #184**, and it does not touch the delegation layer.
- **It does not assume compaction is available**: `DISABLE_COMPACT` turns off even the manual path, so
  the layer's fallback — end and reopen the session — is a first-class path, not an error branch.
