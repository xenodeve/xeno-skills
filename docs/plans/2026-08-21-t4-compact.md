# T4-Compact — the layer outside the session that the agent calls

**Status:** design, not started. **PRD: #304**; slices #305 (probe the transport) · #314 (the supervisor) · #306 (handoff validity) · #307 (the gate) · #308 (the skill) · #309 (restore) · #312 (`t4-agent-memory` row). Tracking issue #310.

> *"สร้าง software layer ครอบให้ model เรียก แล้วจะไป trigger /compact หลังจาก handoff … ตัว Model สั่ง
> Compact เองไม่ได้ … แล้วส่ง Prompt ให้อ่าน handoff ที่ตัวเองเขียนโดยส่ง Path ให้อ่าน"*

> **Revision 3, 2026-08-21.** Revisions 1 and 2 both looked for a way to make compaction happen *from
> inside the session* — first by riding auto-compaction, then by lowering its window. **Both were
> answering a question the developer had already closed.** The premise of the design is that the model
> cannot compact itself, **which is why there is a layer**. The layer is a process outside the session
> that owns it. This revision plans that process.

## 1. The architecture, in one picture

```text
┌─ the layer (a supervisor process) ───────────────────────────────┐
│  spawns:  claude -p --input-format stream-json                   │
│                  --output-format stream-json --session-id <uuid> │
│                                                                  │
│  ① reads the agent's stream, watching for the call               │
│  ② on a call: waits for a VALID handoff at the agreed path       │
│  ③ sends /compact into the session's input stream                │
│  ④ sends the next user message: "read <path>, then continue"     │
└──────────────────────────────────────────────────────────────────┘
        ▲                                        │
        │ ① the agent calls out                  │ ④ the agent reads its own
        │    (Bash, one command)                 │    handoff and continues
   ┌────┴────────────────────────────────────────▼──────┐
   │  the session: skill t4-compact decides the moment  │
   └────────────────────────────────────────────────────┘
```

**Everything the agent cannot do, the layer does, because the layer is not inside the conversation.**

## 2. The transport is real, and these are the flags (verified 2026-08-21, `claude --help`)

| Flag | What it gives the layer |
|---|---|
| `-p, --print` with **`--input-format stream-json`** | *"realtime streaming input"* — the layer **writes user messages into the running session**, which is the whole mechanism |
| **`--output-format stream-json`** | it reads the session's events as they happen, so it can see the agent's call and the compaction result |
| **`--session-id <uuid>`** | the layer chooses the id, so it knows the transcript path without guessing |
| `-r, --resume [id]`, `-c, --continue`, `--fork-session` | the fallback path: end the session and reopen it seeded with the handoff |
| `--replay-user-messages` | messages it injected are echoed back, so injection is **acknowledged rather than assumed** |
| `--autocompact <auto\|tokens>` | a launch-time window, sized per task class — a secondary lever, not the mechanism |
| `--bg, --background` + `claude agents` | a session managed as a background agent, if the layer should not hold the terminal |

**What is not yet verified, and is slice #305:** whether a **slash command** delivered through
`--input-format stream-json` executes as a command (`/compact`, `/handoff`) or arrives as literal text.
The binary shows `processSlashCommand` / `processPromptSlashCommand` and marks `/autocompact`
`supportsNonInteractive`, which is suggestive and **is not evidence**.

**If slash commands do not execute over that transport**, the fallback is already in the flag list and is
arguably better: the layer **ends the session and reopens it** (`--resume --fork-session`, or a fresh
`--session-id`) with the first user message being *"read the handoff at `<path>`"*. That is a harder
reset than `/compact` — nothing stale survives at all — and it is entirely under the layer's control.

## 3. How the agent calls the layer

**The agent has `Bash`. That is the call.** No new tool is needed and none exists — `sdk-tools.d.ts`
lists every tool input type and there is no `SlashCommand` and no compact.

```text
skill t4-compact decides the moment
  → writes the handoff to .claude/t4-handoff/<session-id>.md
  → runs:  .claude/hooks/t4-compact-call <reason>
           (writes .claude/t4-compact/request.json and returns immediately)
  → says one line and stops
```

The layer is watching for that file — or for a sentinel in the output stream, which #305 decides between.
**The agent never blocks on the layer**, because a turn that waits for its own supervisor is a deadlock.

## 4. When the skill calls — the four conditions

| Condition | Checkable form | Ships as |
|---|---|---|
| **A task finished and the next has not started** | the issue closed, nothing new in flight — the agent knows without measuring | **trigger** |
| **Context is long** | the layer sees token usage in the stream; the skill sees turns since the last boundary | **trigger**, threshold measured before it is written down |
| **What is left does not fit the next task** | the change inventory from the survey is larger than the remaining window | **trigger, layer-side** — only the layer has the usage number |
| **Depth raises error risk** | — | **hypothesis.** The adjacent project's depth data reads **100 % (30/30) at 64K** and **100 % (10/10) at a 114,406-token prompt** (`03-DEEP-CONTEXT-QUALITY-REPORT.md`, lines 94 and 160, read directly). One quantization, and *no degradation detected* is not *equivalence shown*. Nothing triggers on it |

**Condition 3 becomes checkable only because the layer exists** — the usage number lives in the stream,
not in the session. That is the second reason for the layer, after the compaction it can perform.

## 5. The guard, and why it stays even though the layer is in charge

```text
NO VALID HANDOFF → NO COMPACT
```

The layer enforces it by construction: it does not send `/compact` until the handoff validates. **The
`PreCompact` hook stays anyway**, because a compaction can still arrive that the layer did not schedule —
the harness's own, at the ceiling.

| trigger | handoff valid | behaviour |
|---|---|---|
| `manual` | yes | allow |
| `manual` | no | **block**, naming the path it looked at |
| `auto` | yes | allow |
| `auto` | no | **allow**, warn, and **record the event** |

Blocking an automatic compaction still wedges a session that is out of room; the recorded rate is what
says whether the skill and the layer are firing early enough. *(Verified: `PreCompact` can block —
`Compaction blocked by PreCompact hook`; `compaction blocked by PreCompact hook; continuing uncompacted`.)*

## 6. Restore: the layer's own next message

The concept's last step — *"ส่ง Prompt ให้อ่าน handoff … โดยส่ง Path ให้อ่าน"* — is the layer writing one
user message after the compaction completes. **That is stronger than the hook path**, because it is a
real user turn rather than injected context, and `--replay-user-messages` acknowledges it.

`SessionStart` (matcher `compact`) and `PostCompact` remain as the **belt** for compactions the layer did
not cause; slice #309 asserts that whichever injection fires **names the handoff by path** — and, per the
addon, the thinking-record map beside it.

## 8. What this plan deliberately does not do

- **It does not put the trigger inside the session.** Revisions 1 and 2 tried; the model has no tool and
  a hook cannot type. The layer exists precisely to hold what the session cannot.
- **It does not automate the console.** The stream-json transport is a supported interface; SendKeys
  against a TUI is not, and would break the first time the terminal changed.
- **It does not re-plan #182 or #184**, and it does not touch the delegation layer.
- **It does not assume compaction is available**: `DISABLE_COMPACT` turns off even the manual path, so
  the layer's fallback — end and reopen the session — is a first-class path, not an error branch.
